# 고객 발견 / 문제 검증

## 검증 실행 계획

### 1단계: 온라인 커뮤니티 조사 (1주)

**목표**: 가설 1(문제 존재), 가설 2(대안 불충분) 검증 데이터 수집

**대상 커뮤니티:**

| 커뮤니티 | 회원 수 | 활용 방법 |
|---|---|---|
| 아프니까 사장이다 (네이버 카페) | ~151만명 | 베이커리/디저트 관련 예약, 노쇼 게시글 분석 |
| 장사의신 (네이버 카페) | ~15만명 | 업종별 게시판에서 디저트/베이커리 검색 |
| 프로페셔널 바리스타 스튜디오 (네이버 카페) | - | 카페/디저트 특화 커뮤니티 |

**수집할 데이터:**

- "예약", "노쇼", "알림톡", "네이버 예약" 키워드 게시글 수 및 내용
- 사장님들이 언급하는 구체적 페인포인트
- 기존 도구(네이버 예약, 카톡 등)에 대한 불만

### 2단계: 인스타 DM 리서치 (1~2주, 1단계와 병행)

**목표**: 가설 1, 2, 3 직접 검증 — **1차는 베이커리/디저트에 집중**, 여유 있으면 인접 업종 5곳 추가 표본으로 확장 가능성 가늠.

**방법:**

- 1차 표본(20~30곳): 인스타에서 "주문제작 케이크", "예약 DM 베이커리", "디저트 픽업" 등으로 검색
- 2차 표본(선택, 5~10곳): 카페·공방·꽃집 등 인접 업종에서 DM 예약을 운영하는 곳
- 짧고 부담 없는 질문 (2~3개)

**DM 메시지 예시 (1차, 베이커리/디저트):**

> 안녕하세요 사장님! 예약 관리 서비스를 준비 중인 개발자입니다.
> 간단한 질문 2개만 여쭤봐도 될까요?
>
> 1. 지금 예약/주문을 어떤 방식으로 받고 계세요?
> 2. 예약 관리에서 가장 불편한 점이 있으시다면요?
>
> 감사합니다!

### 3단계: 랜딩페이지 테스트 (2단계 이후)

**목표**: 가설 3(지불 의향) 검증

**구성:**

- 한 페이지짜리 랜딩페이지
- 핵심 메시지: "노쇼 걱정 없는 베이커리 예약 관리" (1차 베이커리향 랜딩. 추후 업종별 랜딩으로 확장)
- 핵심 기능 3가지 소개 (노쇼 관리, 카카오 알림톡, 낮은 수수료)
- 가격 제시 + "사전 신청" CTA 버튼
- 커뮤니티/인스타에 공유하여 트래픽 유입

**측정 지표:**

- 방문자 수
- 사전 신청 전환율 (목표: 5% 이상)
- 신청자 업종 분포

### 4단계: 판단

| 결과 | 다음 행동 |
|---|---|
| 가설 대부분 검증됨 | PRD 작성 -> 개발 진행 |
| 가설 일부만 검증됨 | 피벗 포인트 파악 후 방향 조정 |
| 가설 대부분 실패 | 프로젝트 방향 재검토 또는 중단 |

## 성공 기준 정리

| 가설 | 성공 기준 |
|---|---|
| 가설 1: 문제 존재 | 커뮤니티 불만 게시글 반복 존재 + DM 응답자 70% 이상 불편함 표현 |
| 가설 2: 대안 불충분 | 네이버 예약 미사용 50% 이상, 또는 사용자 50% 이상 한계점 지적 |
| 가설 3: 지불 의향 | 랜딩페이지 사전 신청 전환율 5% 이상 + DM 응답자 40% 이상 관심 |
| 가설 4: 1인 운영 | MVP 2~3개월 내 출시 + 6개월 내 유료 5곳 + 고객지원 주 5시간 이내 |

## 리스크

- **DM 응답률 저조**: 사장님들이 바빠서 답하지 않을 수 있음 → 20~30곳에 발송하여 모수 확보
- **커뮤니티 홍보 반감**: 광고로 인식될 수 있음 → 순수 리서치 목적으로 접근
- **지금예약 경험 편향**: 과거 경험이 현재 시장을 정확히 반영하지 않을 수 있음 → 최신 데이터로 보완
- **소규모 샘플**: 정확한 통계가 아닌 방향성 확인 수준으로 활용
