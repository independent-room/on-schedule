# 예약톡 Design System

> 베이커리·디저트 사장님을 위한 예약·노쇼 관리 SaaS의 디자인 시스템.
> Wanted Design System(원티드 디자인 시스템, CC BY 4.0)의 색상·타이포 구조를 베이스로,
> 베이커리에 어울리는 따뜻한 캐러멜 톤(브랜드 #E8761A)과
> 노쇼/확정/픽업 등 도메인 특화 시멘틱을 추가했습니다.

## 1. 제품 컨텍스트

**예약톡** — 카톡 DM/인스타 DM으로 예약을 받던 소규모 사장님(특히 **베이커리/디저트**)을 위한 예약·노쇼 관리 SaaS.

**핵심 가치**

1. 노쇼 걱정 없는 예약 관리 — 선결제/보증금, 노쇼 이력 추적
2. 카카오 알림톡 자동 발송 — 확정/리마인드/픽업 완료
3. 네이버 예약 대비 1/9 결제 수수료 (3.74% → 0.4%)

**유저 두 종**

- **사장님 (B2B)** — 데스크톱·태블릿 위주. 예약 캘린더, 고객 CRM, 알림톡, 통계.
- **고객 (B2C)** — 모바일 위주. 가게의 예약 페이지에서 메뉴/시간 선택 → 결제.

**소스 자료** (재현 시 참조)

- Figma: Wanted Design System (Community) (Copy) — `.fig` 파일 형태로 마운트됨, 25 페이지
- 기획 문서: `docs/01.md` ~ `docs/12.md` (서비스 개요, 문제 정의, 타겟, 가치 제안, MVP, 알림톡 전략 등)

## 2. 콘텐츠 파운데이션 (CONTENT FUNDAMENTALS)

### 2.1 톤 & 보이스

- **사장님 친화 + 차분한 전문성.** 헛도는 마케팅 카피 지양. "노쇼 없이 받자"가 아니라 "노쇼 1건당 평균 44.3만원, 선결제로 막을 수 있어요"처럼 구체적 수치/근거를 곁들임.
- **시스템 메시지는 짧고 사실적.** "예약 확정됨", "오후 3시 픽업", "선입금 30,000원 입금 완료" — 군더더기 X.
- **Painkiller 어휘.** 막연한 "관리"보다 "노쇼 막기", "픽업 누락 방지"같이 통증을 직접 짚는 단어를 쓴다.

### 2.2 인칭 / 호칭

- 사장님 화면 → 사장님은 **"나"** (예: "내 예약", "내 가게", "오늘 받은 예약")
- 고객 화면 → 사장님 가게 = **가게 이름 그대로** (예: "베이커리 우진의 예약 페이지")
- 시스템이 사장님에게 말 걸 때 → "사장님" 호칭, 평어가 아닌 **존댓말** ("예약이 들어왔어요")
- 시스템이 고객에게 말 걸 때 → 친근 존댓말 ("3월 14일 오후 3시 픽업이에요!")

### 2.3 표기 규칙

- **혼합 한글/숫자.** 한국어 본문 + 숫자/금액/시간은 그대로 아라비아 숫자 ("3월 14일 오후 3시", "30,000원", "예약 5건")
- **금액 표기.** 천 단위 콤마, "원" 접미사. 큰 수는 "44.3만원" 식으로도 허용.
- **시간 표기.** 기본 "오후 3:00", 짧은 곳에선 "15:00"도 OK.
- **소문자 영문.** 제품명 외 영문은 소문자 (예: "kakao 알림톡", "PG 결제").
- **이모지 사용 안 함.** 디자인 시스템 차원에서 emoji는 인터페이스에 등장시키지 않음. 상태는 컬러 닷·뱃지·아이콘으로 표현.

### 2.4 카피 예시

| 상황 | ❌ 피할 것 | ✅ 권장 |
|---|---|---|
| 빈 상태 | 데이터가 없습니다 | 아직 받은 예약이 없어요 |
| 노쇼 경고 | 주의: 위험 고객 | 이 고객은 최근 3개월 노쇼 2회예요 |
| 알림톡 발송 | 메시지 전송 완료 | 알림톡을 보냈어요 (3건) |
| 결제 | 결제 진행 | 30,000원을 받을게요 |
| 에러 | 오류가 발생했습니다 | 알림톡을 보내지 못했어요. 다시 시도할까요? |

## 3. 비주얼 파운데이션 (VISUAL FOUNDATIONS)

### 3.1 색상

- **뉴트럴**: Wanted DS의 쿨 그레이 스케일 그대로 (`#FFFFFF` → `#17171A`).
- **브랜드(액센트)**: 따뜻한 캐러멜 `#E8761A` (`--c-brand-500`). 빵·디저트·구움색을 떠올리게 하면서, 너무 달지 않은 진한 톤.
- **브랜드 사용 면적은 좁게.** 페이지의 5~10% 이내. 주요 CTA, 강조 숫자, 셀렉티드 상태에만.
- **크림/베이지** (`--c-cream-50/100/200`): 히어로 배경, 빈 상태 일러스트 배경 등에 사용. 흰색 위에 살짝 따뜻한 면을 만들 때.
- **상태색 (도메인 시멘틱)**:
  - confirmed (확정) → `--c-success-500` 그린
  - pending (대기) → `--c-warning-500` 앰버
  - noshow (노쇼) → `--c-danger-500` 레드
  - cancelled (취소) → `--c-neutral-500` 그레이
- 텍스트는 거의 항상 **반투명 블랙**(`rgba(23,23,25,0.95)` 등)을 쓴다. 이 방식은 어떤 배경 위에서도 살짝 가라앉아 자연스럽다 — Wanted DS와 동일한 접근.

### 3.2 타이포

- **본문/UI**: Pretendard JP (한·일·영 모두 자연스럽고 숫자 균형이 좋음). 14~16px, weight 500, line-height 1.5.
- **디스플레이/숫자/대형 헤더**: Wanted Sans (variable). 큰 숫자(매출, 예약 수)나 히어로 타이틀에서 시각적 임팩트.
- **모노**: JetBrains Mono (시간/코드/예약번호). SF Mono 대체.
- **숫자는 tabular-nums.** 표·KPI·시간 정렬을 위해 `font-variant-numeric: tabular-nums`를 numeral 클래스에 기본 적용.
- 한국어 letter-spacing은 마이너스 (-0.024em ~ -0.03em) — 큰 글자에서만. 본문은 +0.006em.

### 3.3 배경

- 기본은 **흰색**. 큰 면을 흰색으로 두고 카드/표/패널이 그 위에 살짝 떠 있는 구조.
- 히어로/온보딩에는 `--bg-hero` (cream-50) 한 톤을 깔아 따뜻함을 준다.
- **그라디언트 거의 사용하지 않음.** 단, 긴 리스트 하단의 fade(흰색 → 투명) 같은 protection gradient는 OK.
- **풀블리드 사진은 신중히.** 베이커리 사진이 뜨거우면 빵 사진이 너무 달아 보이므로 (warm + grain) 톤만 사용. 차가운 푸른빛은 X.

### 3.4 레이아웃 / 그리드

- 데스크톱: 12-col, 1280~1440 max-width, gutter 24~32px.
- 모바일: 16px side padding, 카드 간 12~16px 간격.
- **카드**: 흰색 배경 + 1px 보더(`--line-normal`) + 14~20px 라운드. 섀도우는 hover나 떠 있어야 하는 컴포넌트(드롭다운, 토스트)에만.
- **모서리**:
  - 인풋·작은 버튼 → `--r-s` (6px) ~ `--r-m` (10px)
  - 카드 → `--r-l` (14px) ~ `--r-xl` (20px)
  - 큰 패널/모달 → `--r-2xl` (28px)
  - pill (뱃지·태그) → `--r-pill`

### 3.5 섀도우 / 엘리베이션

4단계만 사용. 더 늘리지 않는다.

- `--shadow-1` — 거의 안 보일 정도. 살짝 떠 있는 인풋·셀렉트의 깊이감.
- `--shadow-2` — 일반 카드 hover 시.
- `--shadow-3` — 드롭다운·메뉴.
- `--shadow-4` — 모달·시트.
- `--shadow-focus` — 캐러멜 톤 포커스 링 (3px alpha 28%).

### 3.6 인터랙션 / 상태

- **Hover**: 표면이 한 단계 어두워짐 (예: 흰색 → `--c-neutral-50`, 캐러멜 → `--c-brand-600`). 텍스트는 absolute 색 변화 없이 underline만.
- **Press**: 추가로 한 톤 더 어둡게(`-700`) + 미세 scale `0.98`. 큰 눌림 X.
- **Focus**: 키보드 포커스에는 항상 `--shadow-focus` 링. 컬러는 캐러멜.
- **Disabled**: opacity 0.4, cursor not-allowed. 회색 회칠 스타일은 안 씀.
- **Selected/Active**: 액센트 보더 `2px var(--c-brand-500)` + 부드러운 배경 `var(--c-brand-50)`.

### 3.7 모션

- **Easing**: standard `cubic-bezier(0.2, 0, 0, 1)`, emphasized `cubic-bezier(0.3, 0, 0, 1)`.
- **Duration**: 120 / 200 / 320ms. 모달·시트는 320, 일반 hover는 120.
- **Bouncy 금지.** 차분한 ease-out 이상의 의인화 없음.
- 알림 토스트는 fade-up 8px + 200ms.

### 3.8 보더

- 1px이 기본. 거의 모든 보더는 `rgba(112,115,124, 0.16~0.40)` 알파.
- 2px은 selected 상태에서만.
- divider는 가로선 1px, 컬러 `--line-subtle`.

### 3.9 투명도 / 블러

- 사이드시트나 모달 위 디머는 `rgba(0,0,0,0.45)`. blur 없음.
- 알림톡 미리보기 등 인앱 카카오톡 스타일은 별도 컬러 시스템(`#FEE500` 카카오 옐로우, `#3B1E1E`) 그대로 사용.

### 3.10 이미지 톤

- 가게 메뉴 이미지: 그대로 노출. crop 1:1 또는 4:5.
- 시스템 일러스트레이션 (빈 상태 등): 라인 위주, 캐러멜 액센트 1색 + 뉴트럴 1~2색. 그라디언트 없음.

## 4. 아이코노그래피 (ICONOGRAPHY)

- **사용 라이브러리: Lucide Icons** ([lucide.dev](https://lucide.dev))
  - 24px 그리드, stroke 1.75 기본. 큰 헤더 아이콘은 stroke 1.5 + 28~32px.
  - CDN 링크: `https://unpkg.com/lucide@latest`
  - **선정 이유**: Wanted DS의 자체 아이콘 폰트가 .fig 안에 있긴 하나(주로 chevron/check/utility), 커뮤니티 라이선스 때문에 코드에 그대로 쓰기는 부담. Lucide는 MIT 라이선스, 같은 톤(line, 24px, stroke 모더레이트)이라 Wanted DS의 시각적 무게와 잘 맞는다. **이 점은 사용자 확인이 필요한 substitution.**
- **폰트 아이콘 사용하지 않음.** SVG 인라인 또는 `<i data-lucide="...">` 방식.
- **이모지 사용 안 함** (콘텐츠 파운데이션 참조).
- **한글 유니코드 글리프** (·, ⌐ 등)는 디바이더·시각 강조에서만 제한적으로 사용.
- **로고/일러스트레이션**:
  - `assets/logo.svg` — 텍스트 워드마크 "예약톡" + 캐러멜 점 액센트.
  - `assets/logo-mark.svg` — 마크만 (아이콘 자리, 16~32px).
  - 일러스트레이션은 line-only, 단색(캐러멜) 또는 듀오톤(캐러멜+뉴트럴 700).

## 5. 폰트 라이센스 / 출처 노트

- **Pretendard / Pretendard JP** — SIL Open Font License 1.1. CDN으로 import.
- **Wanted Sans** — SIL OFL 1.1. CDN으로 import.
- **JetBrains Mono** — Google Fonts에서 로드 (SF Mono 대체).
- 위 폰트는 모두 자유롭게 쓸 수 있어, 별도 fonts/ 동봉은 생략. 오프라인 빌드가 필요해지면 그때 추가.

## 6. UI 키트

| 키트 | 설명 |
|---|---|
| `ui_kits/owner/` | 사장님 웹 대시보드 — 오늘의 예약, 캘린더, 노쇼 관리, 알림톡 발송 모달 |
| `ui_kits/customer/` | 고객 모바일 예약 페이지 — 가게 헤더, 메뉴 선택, 픽업 시간 선택, 결제 |

## 7. 캐비엇 (확인 필요)

- **로고/워드마크**: 실제 로고가 없어 임시 워드마크를 만들었습니다. 실제 로고 첨부 필요.
- **아이콘**: Lucide로 substitute. Wanted DS 자체 아이콘 폰트를 그대로 사용하려면 추가 작업 필요.
- **기술 스택 미정** 상태이므로, 컴포넌트는 React + 인라인 JSX로만 작성. (프로덕션 적용 시 styled-components / Tailwind / vanilla CSS 어떤 것이든 토큰만 import하면 됩니다.)
