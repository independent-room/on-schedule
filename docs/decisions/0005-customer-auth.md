# ADR-0005: 고객 인증 — 무인증 + 모달 확인 + 알림톡 발송 결과 검증

상태: 채택
일자: 2026-05-03

## 컨텍스트

고객 예약 시 신원 검증을 어디까지 강제할지 결정해야 한다. 너무 약하면 가짜/오타 번호로 알림톡 도달 실패 → 노쇼 관리 무력화. 너무 강하면 마찰로 예약 자체를 포기.

베이커리/디저트 예약은 티켓팅과 성격이 다르다:
- 재판매(암표) 가치 0 → 악의적 가짜 예약 동기 거의 없음
- 의도성 높은 구매 (즉흥 X), 단가 높음
- 현재 대안인 DM 예약은 인증 0 → 우리가 마찰 추가하면 대안 대비 열등

비교 가능한 벤치마크: 캐치테이블(소셜 로그인), 콜라보살롱(무인증), Fresha/GlossGenius(무인증) — 베이커리 컨텍스트는 무인증 쪽에 가깝다.

## 검토한 옵션

| 옵션 | 마찰 | 검증 | 비용 | 비고 |
|---|---|---|---|---|
| A. 전화번호만 (인증 X) | 🟢 최저 | 🔴 없음 | 0 | 가짜 번호 그대로 통과 |
| B. SMS OTP 강제 | 🟡 60초 | 🟢 강함 | OTP ~15~30원/건 | 표준 강도, 마찰 큼 |
| C. 카카오 로그인 | 🟢 낮음 | 🟢 강함 | 0 | 어차피 전화번호 별도 입력, 심사 부담 |
| D. 콜백 알림톡 (버튼 클릭) | 🟢 10초 | 🟢 강함 | 알림톡 9원 | OTP 대안, 신박함 |
| E. **무인증 + 모달 확인 + 알림톡 발송 결과 검증** | 🟢 5초 | 🟡 중간 (다중 방어) | 0 | 베이커리 컨텍스트 최적 |

## 결정

**E 채택.** 4-Layer 다중 방어로 OTP 없이도 실용적 검증 효과를 확보한다.

### 흐름

```
1. 메뉴/일시 선택
2. 이름 + 전화번호 입력
3. [예약하기] 클릭
4. 모달: "010-XXXX-XXXX 이 번호로 알림 받으시겠어요?"
   ├─ [수정할게요] → 입력 화면 복귀
   └─ [네, 맞아요] → 예약 완료 + 알림톡 발송
5. 알림톡 결과
   ├─ 성공 → 정상 진행
   └─ 차단/없는 번호 → DB 기록 + 사장님 화면 ⚠ 표시 + SMS 자동 대체발송
6. ⚠ 표시된 예약은 사장님이 직접 전화 또는 거절(자동 환불)
```

### 모달 UX 원칙

- 번호를 크게·굵게 표시 (오타 인지)
- 디폴트 버튼 = **[수정할게요]** (다크 패턴 역방향, 무의식 클릭 방지)
- 자동 닫힘 X
- 라벨은 "네, 맞아요" / "수정할게요" (확인/취소보다 인지 자극 강함)

## 근거

- 베이커리/디저트 컨텍스트에서 OTP 강제는 표준 이상의 마찰 (벤치마크 검증)
- 가짜 번호의 실제 위험은 "장난 예약"이지 "조직적 어뷰징"이 아님 → 사장님 ⚠ + 거절 + 자동 환불로 흡수 가능
- 노쇼 방어의 1순위 무기는 **선결제/보증금**이지 인증이 아님 → 핵심 가치 제안과 정렬
- OTP 도입은 "있을지 모를 문제를 미리 막으려고 확실한 마찰을 만드는 것" → 보통 손해

## 결과

- 모달 컴포넌트 구현 (Next.js 웹)
- 알림톡 차단 코드(KKO_1021/1025/E18) DB 기록 로직
- 사장님 앱 예약 목록에 ⚠ 배지 + 1탭 거절 버튼
- SMS 자동 대체발송 (솔라피 LMS API)
- 데이터 트래킹 이벤트 3개: `phone_modal_shown`, `phone_modal_confirmed`, `phone_modal_edited`

### 재검토 트리거 (데이터 기반 의사결정)

- 가짜 번호로 인한 도달 실패율 X% 이상 → 매장별 OTP 토글(옵션 B) 추가
- 사장님 인터뷰에서 "고객 인증이 있으면 좋겠다"는 응답 50% 이상 → 콜백 알림톡(옵션 D) 추가
- DM 리서치(`04.고객발견.md` 2단계)에서 사장님 의견 수집 시 같이 물어볼 것
