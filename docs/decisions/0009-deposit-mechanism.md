# ADR-0009: 예약금/보증금 메커니즘 — 단계적 진화 경로

상태: 잠정 (1차 단계는 베타 검증 트리거 시 발동)
일자: 2026-05-03

## 컨텍스트

ADR-0007에서 1차 MVP에 결제 모듈을 제외했다. 그러나 베타 운영 중 사장님들이 예약금/보증금 받기를 요구할 가능성은 높다. 이때를 대비해 **메커니즘의 진화 경로**를 미리 정의해 둔다.

핵심 인식: **예약금은 "결제"가 아니라 "노쇼 방지 자금 잠금"** 이다. 매장 매출 본체는 픽업 시 현장 결제다. 따라서 메뉴 전액 결제(ADR-0010)와 다른 설계 원칙이 적용된다.

제약:
- 1인 운영 — 도입 비용 최소화
- 사장님 가입 마찰 최소화 (GTM 핵심 변수)
- 통신판매중개업·정산·분쟁 부담 가능한 한 회피
- 보증금 단가는 1~5만원 — 영세 0.4% 수수료 가치 미미

## 검토한 옵션

| 옵션 | 자동화 | 우리 부담 | 사장님 부담 | 자금 흐름 |
|---|---|---|---|---|
| H. 매장 계좌이체 + 입금 확인 자동화 | 🟡 입금 확인만 자동 | 🟢 거의 없음 | 🟢 자기 계좌만 | 매장 직행 |
| F. 카드 사전승인 보류 (Authorization Hold) | 🟢 완전 자동 | 🟡 PG 가맹 | 🟡 가맹 절차 | 카드사 보류 |
| I. 간편결제 송금 링크 (카카오페이/토스) | 🟡 송금 + 콜백 | 🟢 작음 | 🟢 자기 계좌 | 매장 직행 |
| B. PG + 우리 정산 (포트원 + 토스페이먼츠) | 🟢 완전 자동 | 🟠 통신판매중개업 + 정산 | 🟢 거의 없음 | 우리 경유 |
| G. 가상계좌 정액 (건당 400원) | 🟡 입금 확인 자동 | 🟡 PG 가맹 | 🟡 가맹 절차 | 우리/매장 |

## 결정

**3단계 진화 경로 채택.** 한 번에 다 만들지 않고, 각 단계는 직전 단계의 한계가 명확해진 시점에 도입.

| 단계 | 메커니즘 | 채택 시점 |
|---|---|---|
| **1차** | **옵션 H — 매장 계좌이체 + 입금 확인 자동화 (오픈뱅킹)** | 베타에서 "예약금 받고 싶다" 요구 빈번 시 |
| **2차** | **옵션 F — 카드 사전승인 보류** (한국 PG 지원 확인 후) | 사장님이 환불 자동화·카드 결제 요구 시 |
| **3차** | **옵션 B — 시나리오 B + 포트원** | 매장 50곳+ 또는 ADR-0010 도입 시 통합 |

### 1차 (계좌이체) 흐름

```
고객 예약 폼:
  메뉴/일시 선택 → 이름·전화번호 입력 → 모달 확인
  → "보증금 30,000원을 [매장 계좌]로 24시간 내 입금" 안내
  → 24시간 미입금 시 예약 자동 취소

매장 측:
  - 매장 계좌 등록 (가입 시 1회)
  - 입금 확인 자동화: 오픈뱅킹 API로 매장 계좌 모니터링
    또는 사장님 앱 [입금 확인] 버튼 1탭 (수동, 더 가벼움)
  - 입금 확정 → 알림톡 "예약 확정" 자동 발송

노쇼:
  - 보증금 = 매장 매출 (별도 환불 없음)

정상 픽업:
  - 매장이 보증금 차감하고 잔금만 받기 또는 별도 환불
  - 환불은 매장 직접 처리 (자동화 X)
```

### 1차 → 2차 트리거
- 사장님 인터뷰에서 "환불 자동화 꼭 필요해요" 50% 이상
- 오픈뱅킹 API 비용/안정성 한계 도달
- 매장 50곳 이상으로 수동 처리 한계

### 2차 (카드 사전승인) 사전 확인 사항
- 토스페이먼츠 Authorization Hold 정식 지원 여부
- 보류 기간 한도 (보통 7~30일) — 베이커리 픽업 일정과 맞는지
- 캡처(실청구) UX 매장 친화도

## 근거

- **시나리오 1(예약금)에서는 시나리오 B의 정당성이 약함**: 보증금 단가가 작아 0.4% vs 2.5% 차이가 600원대 → 영세가맹 가치 미미
- **계좌이체는 한국 소비자에게 익숙**한 방식 — 마찰 인지 낮음
- **자금이 우리 계좌를 안 거치면** 통신판매중개업·자금세탁·세금계산서·차지백 부담 동시 회피 → 1인 운영의 가장 큰 무게 회피
- **1차에 포트원 + PG 도입은 과투자** — 아직 결제 자동화의 가치를 사장님이 강하게 요구하는지 검증되지 않음

## 결과

- 1차 단계 도입 시 구현 항목:
  - 매장 계좌 정보 등록·관리
  - 고객 예약 폼에 입금 안내 + 카카오페이 송금 링크 임베드
  - 24시간 미입금 자동 취소 잡 (BullMQ)
  - 오픈뱅킹 API 통합 (선택, 비용·안정성 평가 후)
  - 사장님 앱 [입금 확인] 1탭 버튼 (수동 fallback)
- 가치 제안 카피 갱신: "낮은 결제 수수료" 대신 "노쇼 방어 + 알림톡 자동화"
- DM 리서치(`04.고객발견.md`)에서 추가 질문:
  - "예약금/보증금 받고 계세요? 어떻게 받으세요?"
  - "예약금만 우리가 자동 처리해드리는 모델 어떨 것 같아요?"

### 재검토 트리거
- 1차 단계 운영 6개월 후 사장님 만족도 측정
- 메뉴 전액 결제(ADR-0010) 도입 시 → 메커니즘 통합 여부 결정
- 한국 PG의 카드 사전승인 지원 정책 변경 시
