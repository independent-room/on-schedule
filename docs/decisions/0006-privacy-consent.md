# ADR-0006: 개인정보 동의 — 분리 체크박스 2개([필수] 개인정보 + [필수] 약관)

상태: 채택
일자: 2026-05-03

## 컨텍스트

한국 개인정보보호법(PIPA) §15·§22, 정보통신망법 §50을 준수하면서 예약 폼의 마찰을 최소화해야 한다.

법적 사실:
- §15①4호: "계약 이행을 위한 개인정보 수집"은 동의 없이도 가능 (이론상)
- §22: 동의는 명확히 알리고 다른 동의와 구분해서 받아야 함
- 정보통신망법 §50: 광고성 메시지는 별도 사전 동의 필수
- 14세 미만은 법정대리인 동의 필요

## 검토한 옵션

| 옵션 | 마찰 | 법적 안전 | 분쟁 시 입증 | 비고 |
|---|---|---|---|---|
| A. 처리방침 링크만 노출 (동의 X) | 🟢 최저 | 🟡 §15①4호로 방어 가능 but 모호 | 🔴 약함 | 분쟁/감독 시 위험 |
| B. 단일 전체 동의 체크박스 1개 | 🟢 낮음 | 🔴 §22 위반 | - | 법 위반 (구분 동의 의무) |
| C. **분리 체크박스 2개 ([필수] 개인정보 + [필수] 약관)** | 🟡 약간 | 🟢 안전 | 🟢 강함 | 표준 관행 |
| D. 분리 4개 (개인정보+약관+제3자+위탁) | 🟠 큼 | 🟢 가장 안전 | 🟢 | 1차 MVP에 과함 |

## 결정

**C 채택.** 1차 MVP에는 필수 동의 2개만 받고, 마케팅 동의는 마케팅 메시지 기능 추가 시점에 도입한다.

### UI

```
□ [필수] 개인정보 수집·이용에 동의합니다  [자세히]
□ [필수] 이용약관에 동의합니다           [자세히]

           [예약하기]   ← 두 체크박스 모두 ON 일 때만 활성화
```

### 디자인 원칙
- 디폴트 체크 OFF (다크 패턴 금지, 위반 시 과태료)
- "전체 동의" 단일 체크박스 두지 않음 (§22 위반)
- "자세히" 링크는 모달 또는 새 탭 → 전문 노출
- [예약하기] 버튼 위 직속 위치 (시선 흐름)

### "개인정보 수집·이용 동의" 명시 항목

| 항목 | 내용 |
|---|---|
| 수집 항목 | 이름, 전화번호, 예약 메뉴/일시, 요청사항 |
| 수집 목적 | 예약 접수·확정·픽업 안내, 노쇼 이력 관리 |
| 보유 기간 | 예약 완료 후 1년 또는 마지막 거래일로부터 1년 |
| 거부 권리 | 동의 거부 가능, 단 거부 시 예약 불가 |

## 근거

- §15①4호 "계약 이행"이라는 빠져나갈 구멍이 있어도, 체크박스로 받는 것은 비용 0에 안전 마진이 가장 큼
- 분쟁/감독 시 "동의했다"는 입증이 텍스트만 노출보다 압도적으로 강함
- "분리 체크박스"는 한국 SaaS의 사실상 표준 → 사용자가 익숙함, 마찰 인지 낮음
- 1차 MVP에 마케팅 메시지 기능이 없으므로 광고 동의는 일단 제외 — 기능 추가 시 SHOULD 단계에 같이 도입

## 결과

### 1차 MVP 같이 준비할 정적 페이지
- `개인정보 처리방침` (필수, 법령)
- `이용약관` (필수, 체크박스 받으려면)
- 웹 푸터·예약 페이지 푸터·사장님 앱 설정에서 항상 접근 가능

### 위탁 처리 구조 (인지)
- 법적으로 **사장님(매장) = 개인정보처리자**, 우리(온스케줄) = **수탁자**
- 이용약관에 "개인정보 처리 위탁" 조항 포함
- 처리방침 발행 주체는 일반적으로 "온스케줄이 [매장명]의 위탁 처리"로 표기
- 변호사 자문 30분(~10~30만원) 권장 — 1차 MVP 출시 전 1회

### 14세 미만 처리
- 1차 MVP에서는 "만 14세 미만은 보호자 동의 필요" 한 줄 안내 + 자진 신고 방식
- 강제 검증은 PMF 후 검토

### 재검토 트리거
- 마케팅 메시지 기능 도입 시 → 광고 동의 체크박스 추가
- 14세 미만 신고 사례 발생 시 → 강제 검증 도입 검토
- 개인정보보호법 개정 시 즉시 재검토
