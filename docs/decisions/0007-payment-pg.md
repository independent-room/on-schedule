# ADR-0007: 결제 PG — 1차 MVP에서 결제 모듈 제외

상태: 잠정 (대체 검토 중 → ADR-0009, ADR-0010 참조)
일자: 2026-05-03 (갱신: 2026-05-03)

## 컨텍스트

초기에는 "선결제/예약 보증금" 기능을 1차 MVP MUST로 정의하고 토스페이먼츠를 PG로 채택하려 했다. 그러나 후속 분석에서 다음 사실들이 드러났다:

1. **PG 도입 목적이 "메뉴 전액 결제"가 아니라 "예약금/보증금"** → 결제가 아닌 "노쇼 방지 자금 잠금" 메커니즘
2. **국내 마켓플레이스/예약 플랫폼의 표준은 시나리오 B (플랫폼이 PG 가맹 + 정산 분배)** — 야놀자, 여기어때, 캐치테이블 모두 동일. 시나리오 A(매장 직접 가맹)는 사실상 안 쓰임
3. **예약금만 받는 모델에선 영세가맹 0.4%의 가치가 미미** (보증금 3만원 기준 0.4% vs 2.5% = 차이 630원)
4. **검증이 0%인 상태에서 결제 모듈은 가장 무거운 부담** — PG 가맹·통신판매중개업·정산·분쟁·환불·세금·법무 자문 동시 발생
5. 1인 + 2~3개월 출시 일정에서 결제 모듈 도입은 출시를 1~2개월 지연시키며 그 가치는 검증되지 않음

## 검토한 옵션

| 옵션 | MVP 영향 | 검증 가치 | 우리 부담 |
|---|---|---|---|
| A. 매장 직접 가맹 (토스페이먼츠) | 부담 大 | 낮음 | 가벼움 (사장님이 가입 부담) |
| B. 플랫폼 PG + 정산 분배 (포트원 + 토스) | 부담 大 | 중간 | 큼 (통신판매중개업 + 정산) |
| C. 결제 자체 빼기 + 노쇼 이력 + 알림톡만 | **부담 小** | **높음** (가설 직접 검증) | **거의 없음** |
| D. 매장 계좌이체 + 입금 확인 (예약금만) | 부담 小 | 중간 | 작음 |

## 결정

**옵션 C 채택.** 1차 MVP에서 결제 모듈(선결제/예약 보증금)을 **MUST → SHOULD로 강등**하고 출시 범위에서 제외한다.

PG 선정(토스페이먼츠 vs 포트원) 결정은 **베타 검증 후로 보류**하며, 도입 시점·메커니즘·사업 모델은 ADR-0009(예약금 메커니즘 진화 경로) 및 ADR-0010(메뉴 선결제 본격 도입 시 모델)로 분리한다.

## 근거

- 1차 MVP의 핵심 검증 가설은 "노쇼 관리 + 알림톡 + 운영 효율"이고, 이 중 노쇼 방어는 **선결제 없이도 (1) 노쇼 이력 누적 (2) 알림톡 자동 발송 (3) 사장님 ⚠ 표시 + 거절** 다중 방어로 1차 검증 가능
- "선결제가 정말 필요한가"는 베타 운영 데이터로 검증 가능 — 사장님이 강하게 요구하면 그때 ADR-0009 흐름으로 도입
- 결제 모듈을 빼면 출시 일정이 1~2개월 단축, 매몰비 최소화
- 가치 제안에서 "낮은 결제 수수료"는 후퇴하나, 네이버 예약 대비 차별점("노쇼 관리 + 알림톡 + 직접 확정/거절")은 그대로 유효
