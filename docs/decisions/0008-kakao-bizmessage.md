# ADR-0008: 알림톡 중계사 — 솔라피 (1순위)

상태: 잠정
일자: 2026-05-03

## 컨텍스트

카카오 알림톡은 카카오와 직접 계약하지 않고 **중계사**를 통해 발송한다. 1차 MVP의 핵심 가치 중 하나가 알림톡 자동 발송(예약 확정·전날 리마인드·픽업 완료)이므로 중계사 선정이 필수.

제약:
- NestJS 백엔드에서 발송 (Node SDK 또는 REST)
- 발송 실패 코드(KKO_1021/1025/E18 등) DB 기록 → ADR-0005의 신원 검증 메커니즘과 연동
- SMS 대체발송 지원 (알림톡 차단 시)
- 템플릿 사전 등록 절차 안정성
- 2026.1 친구톡 → 브랜드메시지 통합 변화 대응

## 검토한 옵션

| 옵션 | SDK/문서 | 단가 | 템플릿 등록 UX | 비고 |
|---|---|---|---|---|
| **솔라피** | 🟢 우수, Node SDK 1급 | ~9원 | 🟢 직관적 | 개발자 친화적 1순위 |
| NHN Bizmessage | 🟡 중 | ~9원 | 🟡 중 | 안정성 좋음, 대기업향 |
| Aligo | 🟠 REST만 | ~8원 | 🟠 구식 UI | 가장 저렴 |
| KT BIZ | 🟡 중 | ~9원 | 🟡 중 | KT 인프라 |

## 결정

**솔라피 1순위 채택 (잠정)**.

PoC 단계에서 1주일 사용 후 SDK·문서·템플릿 등록 UX·발송 안정성을 평가하여 채택을 확정한다. 문제 시 NHN Bizmessage로 폴백.

## 근거

- 솔라피 Node SDK는 한국 알림톡 중계사 중 가장 개발자 친화적 (TypeScript 타입, 에러 핸들링, 웹훅 표준화)
- 문서가 영문 수준 — AI 도구가 코드 생성하기 좋음
- 알림톡 + SMS 대체발송 단일 SDK
- 템플릿 등록 대시보드 UX가 직관적 (템플릿 수정 빈도 높은 초기에 가치 큼)

## 결과

### 외부 사업자 등록 (출시 전 필수)
- 솔라피 계정 + 발신 프로필 등록
- 사업자등록증 + 통신판매업 신고증 준비
- 카카오 비즈니스 채널 개설 (서비스 자체 채널) — 매장 채널 미연동 시 발송용
- 템플릿 사전 등록 (예약 확정 / 전날 리마인드 / 픽업 준비완료 / 노쇼 경고 등)

### 구현 항목
- NestJS `NotificationModule` — 솔라피 SDK 래핑
- 발송 큐 (BullMQ) — 리마인드 스케줄러
- 차단 코드 처리 (KKO_1021 등) → DB 기록 → ADR-0005의 사장님 ⚠ 표시
- SMS 자동 대체발송 로직 (사장님 토글)
- 발송 비용 집계 (월별 매장별)

### 채널 전환 (매장 비즈니스 채널 등록 후)
- 매장이 자기 비즈니스 채널 등록 완료 → 발송 채널을 매장 채널로 전환
- 미등록 시 온스케줄 플랫폼 채널("[온스케줄] 알림")로 발송
- 콜라보살롱 방식 참고 (`docs/00.기획/10.레퍼런스서비스.md`)

### 2026.1 변화 대응
- 친구톡 → 브랜드메시지 통합 영향 분석 (마케팅 메시지 한정, 정보성 알림톡은 영향 X)
- 마케팅 메시지 기능 자체가 1차 MVP에 없으므로 SHOULD 단계에서 본격 대응

### 재검토 트리거
- 솔라피 발송 안정성 문제 발생 시 → NHN Bizmessage 전환
- 솔라피 정책/단가 큰 변경 시
- 일일 발송량 1,000건 초과 → 한도 상향 요청 + 안정성 재평가
