# ADR-0001: 포지셔닝 — 범용 예약 SaaS · 베이커리는 1차 GTM

상태: 채택
일자: 2026-05-03

## 컨텍스트

초안 문서에는 "베이커리/디저트 특화 SaaS"라고 표현돼 있었으나, 실제 의도는 **확장 가능한 범용 예약 서비스**이며 베이커리는 비치헤드(beachhead) 시장이다.

제약:
- 지금예약(과거 시도)의 실패 원인 중 하나가 "타겟 분산"이었음 → 초기 GTM은 한 곳에 집중해야 함
- 동시에 1년 후 인접 업종으로 확장 가능해야 — 시장 천장 확보
- 한국에 베이커리/디저트 특화 예약 SaaS는 부재 → 진입 공백이 가장 명확한 시장

## 검토한 옵션

| 옵션 | 장점 | 단점 |
|---|---|---|
| A. 베이커리/디저트 특화 SaaS로 정체성 고정 | 메시지 명확, 도메인 깊이 ↑ | 인접 업종 확장 시 리브랜딩 필요, 시장 천장 작음 |
| B. 처음부터 멀티 업종 동시 공략 | 시장 큼 | 지금예약 실패 재현 위험, 1인 운영 불가 |
| C. **범용 코어 + 베이커리 1차 GTM** | 확장성 + 집중 동시 확보, 코드 추상화 유지 | 마케팅 카피·도메인 설계에 추상화 비용 |

## 결정

**C 채택.** 제품은 업종 비종속적인 범용 예약/주문 관리 코어로 만들고, 마케팅·콘텐츠·랜딩은 1차로 베이커리/디저트에 집중한다.

확장 경로: 베이커리/디저트 → 카페 → 공방/원데이클래스 → 꽃집 → 정육/반찬 → 소규모 스튜디오 등 예약형 소상공인 전체.

## 근거

- 지금예약 실패 원인을 "타겟 분산"으로 분석했지만, 실패의 본질은 "타겟 분산 + 깊이 부족"이지 "타겟이 여러 개라는 사실 자체"는 아님. 코어가 범용이어도 GTM을 한 곳에 집중하면 동일 효과를 얻을 수 있음.
- 베이커리/디저트로만 고정하면 시장 천장이 작아 1인 사이드 프로젝트 이상으로 키우기 어려움.
- 범용 코어로 만들어도 1차 마케팅 메시지·UI 카피·세그먼트 정의는 베이커리에 맞게 좁혀 운영 가능.

## 결과

- 도메인 모델·DB 스키마는 업종 확장 가능하도록 추상화 유지 (예: "메뉴/슬롯/리소스" 명칭과 구조)
- 시장 규모(`07.시장규모.md`) TAM/SAM 2단 추정: SAM-A=베이커리/디저트, SAM-B=확장 시장
- GTM(`12.유저획득전략.md`) 단계 분리: 1단계=베이커리, 2단계=인접 업종
- 문서·코드·UI 카피에서 "베이커리 특화 SaaS"라는 표현 금지

### 재검토 트리거
- 베타 6개월 운영 후 베이커리/디저트 외 업종에서 자발적 가입 N건 이상 → 2단계 GTM 시작 시점
- 베이커리에서 PMF 미달성 1년 → 포지셔닝 재고
