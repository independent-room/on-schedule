# 엣지 케이스 대응 전략

예약 서비스 운영 중 발생 가능한 엣지 케이스를 자동 대응 가능 여부로 분류하고, MVP 포함 범위를 정의한다.
경쟁사 조사 결과(2026-04-10)를 반영하여 대응 방식과 기준을 구체화했다.

---

## 자동 대응 가능 (코드로 해결)

### A. 입력 오류

| 1 | 전화번호 형식 오류 (숫자 아님, 자릿수 다름) | 정규식 검증으로 입력 차단. 11자리(01012345678)만 허용 | ✓ |

> **기존 오류 수정**: 카카오 채널 차단은 알림톡에 영향 없음 (알림톡은 채널 추가 불필요). "7일 미접속"이 실질적 실패 원인.
> **기존 오류 수정**: 카카오 공식 일일 발송 한도는 없음. 중계사 계약 한도만 존재.
> **기존 오류 수정**: 중계사가 24시간 내부 재시도를 수행하므로 서비스 단 재시도 큐는 불필요. 500 에러 로깅만.

## 설계 원칙

### 1. 자동 대응 케이스는 반드시 구현

MVP 35건 중 자동 대응 가능한 케이스는 전부 코드로 해결한다.

### 2. 사장님에게 수정 권한을 충분히 줘라

사장님 대시보드에서 다음이 가능해야 한다:
- 예약 정보 수정/삭제
- 고객 프로필 수정/삭제/병합 (v2)
- 마케팅 동의 상태 수동 조정
- 노쇼 처리/취소/차단 해제
- 블랙리스트 관리 (v2)

### 3. 고객에게 오류 신고 경로를 열어둬라

- 모든 마케팅 알림톡 하단 수신거부 링크 (법적 필수)
- 고객 전용 페이지 (전화번호 기반, 본인 정보 수정)
- 예약 취소/수정 링크 (알림톡 내 포함)

### 4. 로그 시스템 필수

다음 이력을 전부 저장:
- 동의 이력 (언제, 어떤 경로로, 어떤 상태로 변경)
- 예약 수정 이력 (누가, 무엇을, 언제)
- 발송 이력 (알림톡/SMS, 성공/실패, 중계사 응답 코드)
- 노쇼 처리 이력
- 고객 병합 이력 (v2)

### 5. 완벽 추구 금지

53건 전부를 MVP에 넣지 않는다. 빈도 높은 것부터 우선.

## 경쟁사 조사 기반 참고사항

### 고객 병합 (경쟁사 조사 2026-04-10)
- **업계 표준**: 감지는 자동, 실행은 수동. 자동 병합은 없음
- **팅커뷰**: 수동 병합 + 이름 재입력 확인 + 고객 연결(가족 공유)
- **핸드SOS**: "이름 + 전화번호 뒷자리" 휴리스틱 중복 후보 감지
- **OpenTable**: 프로필 소유권 3종 구분, Hide 후 자동 복원
- **네이버 예약/캐치테이블**: 계정 기반이라 병합 개념 없음

### 알림톡 발송 (경쟁사 조사 2026-04-10)
- **채널톡**: SMS 자동 대체 미제공 (의외)
- **공비서**: 자동 SMS 대체 없음, 수동 재발송
- **솔라피**: 대체 발송 기본 ON, 초기 중계사로 추천
- **카카오 공식**: 서버가 24시간 내부 재시도. 서비스 단 재시도 큐 불필요

### 노쇼 처리 (경쟁사 조사 2026-04-10)
- **캐치테이블**: 1회 경고 → 2회 제한 → 3회 정지. "예약금 0원 결제"로 노쇼율 20% → 1% 미만
- **테이블매니저**: 3단계 자동 분류, 노쇼율 3.78% → 1.09%
- **팅커뷰**: 노쇼 1회 = 블랙리스트 세그먼트 자동 분류 (차단 미연결)
- **공비서/콜라보살롱**: 예약금만 유일한 방지 수단
- **공정위 2026**: 일반 음식점 보증금 최대 20%, 예약 기반 업종 최대 40%

### 선결제/보증금 우선순위 재검토 → ADR-0007/0009로 결정 갱신

| 시점 | 이전 결정 | 현재 결정 (ADR 반영) |
|------|---------|------------------|
| MVP | "v2 격상 검토" | **결제 모듈 자체 제외** (ADR-0007) |
| 베타 검증 후 | - | **3단계 진화 경로 발동** (ADR-0009) |

**ADR-0009 3단계 진화 경로:**
1. **1단계 (베타 트리거 시)**: 매장 계좌이체 + 입금 확인 자동화 (옵션 H) — 우리 부담 최소
2. **2단계**: 카드 사전승인 보류 (Authorization Hold) 또는 간편결제 송금 링크 (옵션 F/I)
3. **3단계 (PMF 후)**: PG 정산 분배 (옵션 B, 토스페이먼츠/포트원)

**MVP 시점에는 결제 자체 없음**. 노쇼 방지는 알림톡 + 노쇼 이력 단계별 처리만 사용.

### 고객 인증 정책 (ADR-0005)

**무인증 + 모달 확인 + 알림톡 발송 결과 검증.**
- 고객은 별도 가입 없이 예약 가능
- 예약 시 전화번호로 본인 확인 모달
- 알림톡 발송 성공 = 유효한 번호 검증 (실패 시 SMS 폴백)
