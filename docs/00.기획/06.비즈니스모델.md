# 비즈니스 모델

## 수익 모델: 단일 플랜 월 구독

무료 플랜 없음. 30일 무료 체험 후 유료 전환.

### 이유

- 1인 운영에서 무료 유저 CS 감당 불가
- 무료 예약이라고 해놓고 알림톡 유료이면 사장님이 배신감 느낌
- 빠른 매출이 필요한 부트스트랩 — 전환 기다릴 여유 없음
- 네이버 예약이라는 무료 대안이 이미 존재 — "무료"로는 차별화 안 됨

### 가격 전략

| 단계 | 가격 | 포함 기능 | 시점 |
|------|------|----------|------|
| MVP | **14,900원/월** | 예약관리 + 예약링크 + 수량제한 + 알림톡 무제한 + 노쇼관리 | 출시 |
| v3 | **19,900원/월** | 위 + CRM + 매출대시보드 + RAG 챗봇 (AI CS) | RAG 챗봇 추가 시 |

### 공비서 벤치마크

- **2016.9 창업, 2026 기준 6.9만 매장, 월 80만 건+ 예약**
- 초기엔 소규모·중간 단가로 시작 → 매장 수 축적 후 중계사 단가 협상으로 원가 절감
- 현재 "알림톡 무료 무제한"으로 마케팅 (월 28,000원 상당 알림톡 비용을 SaaS가 흡수)
- 투자 0건으로 자체 수익 성장 (연평균 123%)
- 본인 서비스도 동일 패턴 가능하지만 **초기 100~500곳 구간 마진 낮음 감수 필요**

## 결제 모듈 정책 (ADR-0007)

**1차 MVP에서 결제 모듈 제외.** 출시 범위 단순화 + 검증 우선.

| 단계 | 결제 처리 |
|------|---------|
| **MVP** | 결제 모듈 자체 없음. 노쇼 이력 + 알림톡으로만 노쇼 방지 |
| **베타 검증 후** | 예약금/보증금 도입 (ADR-0009 3단계 진화 경로) |
| **PMF 후** | 메뉴 전액 결제 도입 (ADR-0010 시나리오 B) |

**근거:**
- PG 도입은 통신판매중개업·정산·분쟁·환불·세금·법무 동시 발생 → 1인 부담 큼
- 검증이 0%인 상태에서 결제 모듈은 가장 무거운 부담
- 출시 1~2개월 지연 가치 미증명

## 사장님 구독료 결제 (ADR-0012)

**Multiplatform Service 패턴 채택. IAP 비채택.**

| 단계 | 방식 |
|------|------|
| **베타** | 수동 입금 확인 (사장님이 계좌이체) |
| **본격 출시** | 포트원 + 웹 결제 자동화 (Apple/Google IAP 비채택) |

**근거:** 모바일 앱에서 결제 강제 시 IAP 30% 수수료 → 웹 결제로 회피.

## 구독 환불 정책 (ADR-0013)

| 단계 | 정책 |
|------|------|
| 베타 | 수동 환불 (요청 시 즉시 처리) |
| **본격 출시** | Smart Retry (3회 재시도) + 일할 환불 + 30일 데이터 보관 |

## 알림톡 비용 정책

- 예약 알림(확정/리마인드/완료): **무제한 포함**
- 마케팅 메시지(홍보/프로모션): **별도 과금 (건당)** — 추후 도입
- 사용량 제한/크레딧 시스템 없음 — UX 최악이므로 도입 안 함
- "잘 되다가 갑자기 안 됨" 상황 방지가 원칙

### 이용약관 예외 조항 (대량 사용 매장 방어)

99%의 소규모 매장은 "무제한 무료" 체감하되, 극단적 대량 사용은 약관으로 방어.

> **예시 문구:**
> "정상적인 예약 운영을 현저히 초과하는 알림톡 발송(월 3,000건 이상)이 지속될 경우, 회사는 상위 플랜 전환 또는 별도 협의를 제안할 수 있습니다."

- 기준: 월 알림톡 발송 **3,000건 이상** (예약 기준 약 1,000건/월 = 일 33건)
- 트리거 시 자동 차단 아님. **사장님 대시보드 경고 + 상담 안내**
- 공비서도 유사 방식으로 관리 중으로 추정 (명시 약관은 불명)
