# 기능 백로그

MVP 로드맵(08.MVP기능정의) 외에 검토 중인 기능 후보를 정리. 각 기능에 대한 시장성·리스크·우선순위 평가 포함.

> **중요 결정 (2026-04 업데이트):**
> - **단계별 셋업 위저드는 MVP 핵심 기능으로 확정** (08번 문서 참조)
> - "랜딩페이지 빌더(아래 후보 #1)"는 여전히 제외 — 페이지 빌더와 단계별 셋업은 다른 개념
> - **예약 폼을 사장님이 단계별로 만드는 것 = MVP**
> - **사장님 가게 홍보용 랜딩페이지를 AI가 만드는 것 = 제외**

## 평가 기준

| 항목 | 설명 |
|------|------|
| 시장 가치 | 사장님이 실제로 원하고 돈을 낼 의향이 있는가 (1~10) |
| 차별화 기여 | 본인 서비스 포지셔닝에 도움이 되는가 (1~10) |
| 구현 난이도 | 1인 부트스트랩으로 만들 수 있는가 (1~10, 낮을수록 쉬움) |
| 범위 적합성 | 핵심(예약+CS+CRM) 정체성에 맞는가 (1~10) |
| **종합 우선순위** | MUST / SHOULD / LATER / 제외 |

## 후보 #1. AI 사장님 랜딩페이지 생성

### 개요

사장님이 자기 가게 홍보 페이지를 AI로 쉽게 만들도록 지원하는 기능. 카페24가 최근 도입한 AI 페이지 빌더 참고.

### 시장 분석

| 항목 | 분석 |
|------|------|
| 사장님 니즈 | 인스타 프로필 + 네이버 플레이스가 이미 무료 랜딩 역할 수행 중 |
| 별도 랜딩 만들 의향 | 매우 낮음 — 대부분 사장님은 인스타·네이버로 충분 |
| 경쟁 도구 | Imweb, Cafe24, 식스샵, Wix 등 전문 빌더 다수 |
| 본인 서비스 중복 | **예약 링크(링크인바이오형)**가 이미 핵심 유입 페이지 역할 |

### 카페24 AI 페이지 빌더 실제 조사

| 항목 | 내용 |
|------|------|
| 정식 명칭 | 카페24 PRO |
| 실제 기능 | **이커머스 쇼핑몰 상세페이지 자동 생성** (고객 후기 기반) |
| 타겟 | 온라인 쇼핑몰 운영자 |
| 예약 서비스와 관계 | **거의 없음** — 상품 판매 페이지 자동화에 특화 |
| 결론 | 본인 서비스(예약 SaaS)와 다른 영역. 직접 차용 불가 |

### 리스크

- **범위 폭발**: AI 페이지 빌더는 별도 제품 수준 개발 필요 (수개월)
- **포지셔닝 혼란**: "예약 SaaS"인지 "페이지 빌더"인지 모호해짐
- **경쟁사 압도적**: Imweb·Cafe24가 이미 수년간 자리 잡음
- **유지보수 부담**: 디자인 템플릿 관리 + 호스팅 비용 추가

### 평가

| 항목 | 점수 |
|------|------|
| 시장 가치 | 3/10 (대안이 너무 많음) |
| 차별화 기여 | 2/10 (예약 SaaS 정체성과 무관) |
| 구현 난이도 | 8/10 (어려움) |
| 범위 적합성 | 2/10 (정체성 흐림) |

**우선순위: 제외**

### 메모

- 사장님이 진짜 원하는 건 **"예약을 받는 페이지"**이지 **"홍보 랜딩"**이 아님
- 이미 제공하는 예약 링크가 그 역할을 함
- 만약 커스터마이징 니즈가 있으면 **예약 링크 디자인 템플릿 옵션** 정도로 흡수 가능 (별도 페이지 빌더 아님)

## 후보 #2. 멀티채널 채팅 통합 (카톡/인스타/네이버톡톡)

### 개요

사장님이 여러 채널(카톡 채널, 인스타 DM, 네이버 톡톡)에서 받는 고객 문의를 한 화면에서 처리. AI 챗봇이 1차 응대, 사장님이 필요시 직접 답변.

### 시장 분석

| 항목 | 분석 |
|------|------|
| 사장님 니즈 | **매우 높음** — 03.타겟고객에 명시: 카톡 DM + 인스타 DM + 네이버 톡톡 혼용 |
| 페인포인트 | 채널마다 알림 따로 확인, 답장 누락, 일관성 없는 응대 |
| 경쟁 도구 | 채널톡(통합 채팅)이 가장 가깝지만 자영업 타겟 아님, 72,000원/월 |
| 본인 서비스 적합성 | 핵심 가치 제안 "채널톡의 예약 버전"과 정확히 일치 |

### API 연동 가능성

| 채널 | API 가능성 | 제약 |
|------|----------|------|
| 카카오톡 채널 (상담톡) | **가능** | 카카오비즈니스 공식 API, 사업자 채널 필수 |
| 인스타 DM | **가능** | Meta 검수, 24시간 윈도우, 시간당 200 DM |
| **네이버 톡톡** | **매우 제한적** | 스마트스토어/플레이스 한정, 독립 SaaS 연동 거의 불가 |
| SMS/문자 | 가능 | 솔라피 등 중계사 |

### 리스크

- **네이버 톡톡 미지원** = 사장님 핵심 채널 하나 빠짐. 마케팅에서 "전 채널 통합" 표현 못 씀
- Meta 인스타 검수 통과까지 **수주~수개월** 소요
- 실시간 채팅 = 운영 부담 (응답 속도 기대치 상승)

### 평가

| 항목 | 점수 |
|------|------|
| 시장 가치 | 8/10 (실제 페인포인트 큼) |
| 차별화 기여 | 9/10 (채널톡 모델의 핵심) |
| 구현 난이도 | 7/10 (Meta 검수 등 어려움) |
| 범위 적합성 | 9/10 (정체성과 일치) |

**우선순위: SHOULD (이미 v3에 포함)**

### 메모

- 08.MVP기능정의 v3 로드맵에 이미 "RAG 챗봇 + 실시간 채팅(기존 모듈 연결)" 포함
- 메모리에 "채팅 모듈 보유" 기록됨 — 활용 가능
- **네이버 톡톡 연동 가능 여부 사전 조사 필요**. 불가능하면 마케팅에서 약속 금지
- 인스타 DM 연동은 v4로 분리 (Meta 검수 오래 걸림)

## 후보 #3. 플랫폼 프로덕트 (마케팅 → 예약 인계)

### 개요

별도 B2C 플랫폼/마켓플레이스를 만들어서 고객을 모은 뒤, 가입 사장님 매장에 예약을 인계하는 모델. 캐치테이블·카오르 같은 구조.

### 시장 분석

| 항목 | 분석 |
|------|------|
| 시장 존재 | 캐치테이블(레스토랑), 카오르(레터링 케이크), 솜씨당(원데이클래스) 등 다수 점유 |
| 진입 장벽 | **매우 높음** — 마켓플레이스는 양면 시장(사장님+소비자) 모두 모아야 함 |
| 자본 요구 | 캐치테이블 수백억 투자, 콜라보살롱 45억 투자 등 |
| 본인 서비스 정체성 | 01.서비스개요에 **"마켓플레이스 아닌 도구형"** 명시 |

### 리스크

- **지금예약 실패 원인 재연**: 타겟 분산 + 기능 중구난방
- **1인 부트스트랩 불가능**: 두 프로덕트 동시 운영
- **사업 모델 전환**: 도구형(B2B) → 마켓플레이스(B2C) = 사실상 다른 사업
- **기존 결정 파기**: 01.서비스개요 포지셔닝 무효화

### 평가

| 항목 | 점수 |
|------|------|
| 시장 가치 | 7/10 (시장은 있음) |
| 차별화 기여 | 1/10 (정체성 파괴) |
| 구현 난이도 | 1/10 (1인 불가능) |
| 범위 적합성 | 1/10 (도구형과 모순) |

**우선순위: 제외 (강하게)**

### 대안 — "마케팅 지원"이 목적이라면 별도 플랫폼 없이 가능

| 기능 | 시점 | 효과 |
|------|------|------|
| CRM 자동화 | v2 | 단골 재방문 트리거 메시지 |
| 마케팅 메시지 (세그먼트) | v3 | 휴면 고객 재유치 |
| 리부킹 리마인더 | v3 | 마지막 방문 N일 후 자동 메시지 |
| 생일/기념일 마케팅 | v4 | 쿠폰 자동 발송 |
| 인스타그램 연동 (예약 유입) | v4 | 댓글/DM → 예약 링크 자동 안내 |

이미 로드맵에 있는 기능들로 마케팅 효과 충분히 낼 수 있음. **별도 플랫폼 필요 없음.**

### 메모

- 만약 정말 플랫폼이 가고 싶으면, **MVP가 1년 이상 안정화되고 매장 1,000곳 넘은 후** 별개 사업으로 검토
- 그 전엔 거론 금지. 1인 부트스트랩 단계에선 자살행위
- 본인이 이 기능을 다시 꺼낼 때마다 **"01.서비스개요 포지셔닝과 충돌"**임을 상기할 것

## 백로그 운영 원칙

1. **MVP 출시 전에는 추가 기능 검토 금지**. 빌드 집중
2. **MVP 출시 후 사장님 인터뷰**에서 반복적으로 나오는 요청만 우선순위 재평가
3. **"있으면 좋겠다"는 추가 근거 아님**. 페인포인트 정량 확인 후 결정
4. **08.MVP기능정의의 LATER**와 본 백로그 분리: LATER는 "다음 메이저 버전 후보", 백로그는 "검토 단계 아이디어"
5. 신규 기능 추가 제안 시 본 문서에 평가 포함하여 의사 결정
